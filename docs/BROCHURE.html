What Recoll Next is

Imagine one computer holding class notes, reports, PDFs, books, meeting records, and project files. Ordinary folders help you browse, but they do not always help you find an idea whose exact words you have forgotten.

Recoll Next combines four local helpers:

Recoll: the librarian

Reads many file types, makes a searchable index, and finds exact words and document details.

Semantic search: the idea matcher

Finds passages that mean something similar even when they use different words.

Ollama: the local explainer

Organizes selected passages into an answer, summary, timeline, decision list, or action list.

Citations: the evidence trail

Connect each accepted AI answer to the exact passages and original files used.

The most important rule: AI is a helper, not the authority. Your original files and Recoll's index stay in charge.

A one-minute story: the science-fair question

Maya has 200 notes about a school garden. She asks, “Why did the tomato plants grow slowly?”

  1. Exact search finds notes containing words such as “tomato,” “slow,” and “growth.”
  2. Concept search may also find “not enough sunlight” and “soil stayed too wet,” even without the word “slowly.”
  3. Maya reads the evidence cards and selects the useful passages.
  4. The local AI makes a short explanation and cites those passages.
  5. Maya opens the original notes to check the answer before using it in her report.

This is evidence exploration: the software helps Maya investigate; it does not ask her to believe an answer with no proof.

What happens when you ask a question

  1. Index: Recoll has already made a map of words and facts about your files.
  2. Retrieve: Recoll Next finds a small group of likely passages.
  3. Inspect: you can read those passages before asking AI to explain them.
  4. Interpret: Ollama receives only the bounded evidence selected for the task.
  5. Validate: the program rejects missing or made-up citation IDs.
  6. Verify: you can open the original document and judge the result yourself.

“Bounded” means limited on purpose. The model receives a small evidence set rather than being invited to guess from everything.

Why "local-first" actually means it

Loopback only, by policy

The AI connection points back to this same computer. The program rejects ordinary internet or local-network addresses under its default policy.

No cloud models, by default

Cloud model identifiers and non-loopback endpoints are rejected by the default configuration. Changing that is a deliberate, governed policy change.

Content stays out of logs

Full documents, private prompts, and credentials are excluded from diagnostic logs and the event ledger — which record identifiers and measurements, not bodies of text.

Derived data is disposable

The idea-matching database can be rebuilt. Deleting it does not delete the original documents or Recoll's ordinary search index.

Local-first is a strong default, not a promise that every local process is harmless. The computer owner still needs normal account security, disk encryption, private backups, and trusted document-reading tools.

The Polaroid and Prism model

Every result starts life as a Polaroid — a stable, factual evidence card: title, path, date, matching terms, the actual passage, and exactly why it was retrieved. The Polaroid layer contains no AI-generated facts and works completely on its own.

On top of that evidence, Ollama can apply a Prism — a selectable lens that organizes the same evidence differently. A lens is an interpretation, never a mutation: selecting one never hides the underlying evidence cards.

  • Exact
  • Concept
  • Timeline
  • People
  • Decision
  • Action
  • Agreement
  • Contradiction
  • Origin
  • Novelty

Today's desktop workspace implements the answer, summary, timeline, contradiction, decision, and action views over this same evidence-first foundation.

In simpler words: the Polaroid is “what the source shows.” The Prism is “one useful way to look at it.” You can always return to the source.

Cited answers, not confident guesses

When you ask a question, the model receives a bounded set of retrieved passages and must return citations alongside its answer. Before anything reaches the screen:

  • every cited segment ID must have actually been supplied to the model;
  • every cited segment must still resolve inside the live Recoll index;
  • an answer with an invented, malformed, or unresolved citation is rejected outright — never silently repaired to look trustworthy;
  • the exact rank and identity of the evidence you selected is re-verified against a fresh search immediately before generation, so you're never interpreting evidence that quietly changed underneath you.

When evidence is absent, conflicting, or thin, the system is designed to say so rather than paper over the gap with fluent prose.

A citation is a trail, not a truth stamp. The validator proves that a cited passage was supplied and still exists. A person should still check whether the AI understood that passage fairly.

Perspective Memory

Answers you choose to keep are stored as secondary local memory — never as primary documentary fact. A later memory search only returns a saved perspective if its cited segment, document, and source revision still resolve; once a source changes, the stale memory is suppressed rather than surfaced as current. Use --no-remember for anything ephemeral or sensitive.

Think of this as a notebook of earlier AI explanations with source labels attached. It is not allowed to turn an old explanation into a new primary fact.

A tamper-evident history

Major architectural decisions and milestones are recorded as a hash-chained, append-only event ledger — each entry references the previous entry's hash, and the chain is independently verifiable at any time:

python src/semantic/rclsem_ledger.py verify governance/events.jsonl

The ledger records what happened and why, in privacy-safe terms — never full documents, prompts, or credentials — and checkpoints of the verified head are kept in governance/CHECKPOINTS.md for independent readability.

A hash chain is like a lab notebook whose numbered pages each include a fingerprint of the page before it. Changing an old page breaks the later links. It detects many changes, but it cannot stop someone from replacing the entire notebook and every separately saved checkpoint.

Architecture at a glance

Original files
  -> Recoll extractors and metadata filters
  -> Xapian lexical index (authoritative document inventory)
  -> deterministic, source-preserving segments
  -> local Ollama embeddings
  -> SQLite semantic namespace (disposable, rebuildable sidecar)
  -> Xapian-first Exact / Prismatic (RRF) / Conceptual retrieval
  -> bounded local Ollama generation
  -> citation validator (fail-closed)
  -> optional Perspective Memory
  -> Tk workspace / native Qt AI dock

Cross-cutting: runtime JSONL ledger + versioned project governance chain

See the full Architecture and Xapian-First Hybrid Search Protocol documents for the normative detail behind this diagram.

Why are there two indexes?

Recoll/Xapian is the trusted word-and-document index. SQLite stores rebuildable vectors for idea matching. Keeping them separate means ordinary search can survive an AI outage or a damaged semantic store.
